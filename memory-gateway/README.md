# Облачная память Jarvis Mobile

Этот каталог — отдельный серверный шлюз для одного пользователя. Мобильное приложение ищет релевантные воспоминания перед запросом GigaChat и сохраняет диалог после показа ответа. Без настройки или при сетевой ошибке используется локальная память. Данные хранятся в Redis Agent Memory; история дополнительно записывается как эпизодическая память с явным владельцем, поэтому поиск не зависит от настройки фонового извлечения фактов.

## Настройка

1. Создайте Redis Agent Memory store в Redis Cloud.
2. Разверните каталог `memory-gateway` как отдельный проект Vercel с Node.js 22.
3. В серверных переменных окружения задайте:
   - `AGENT_MEMORY_BASE_URL`: HTTPS URL из Redis Cloud.
   - `AGENT_MEMORY_STORE_ID`: ID хранилища.
   - `AGENT_MEMORY_API_KEY`: ключ Redis store; только на сервере.
   - `JARVIS_MEMORY_TOKEN`: случайный токен не короче 32 символов, например результат `openssl rand -hex 32`.
   - `JARVIS_MEMORY_OWNER_ID`: постоянный ID пользователя из букв, цифр и дефисов (до 64 символов). По умолчанию `jarvis-mobile-user`. При смене токена сохраните этот ID для доступа к прежней памяти.
4. В приложении откройте настройки облачной памяти. Введите `https://<ваш-домен>/api/memory` и `JARVIS_MEMORY_TOKEN`, затем сохраните.
5. Задайте вопрос Jarvis. Настройки показывают результат последнего обращения к облаку.

Один шлюз и токен предназначены одному пользователю. Владелец памяти определяется сервером, а не полем запроса. Для разных пользователей создайте отдельные шлюзы с разными токенами и ID владельцев либо реализуйте полноценную авторизацию.

Кнопка отключения прекращает новые обращения. Уже сохранённые данные остаются в Redis; локальная команда «забудь» не удаляет облачную историю. Удаление облачных данных выполняется отдельно в Redis Cloud/API. Это первая версия интеграции: синхронизации офлайн-очереди и экранов управления облачными воспоминаниями пока нет.

## Проверка и сборка

- `npm ci && npm test` в этом каталоге: авторизация, валидация, работа установленного Redis SDK с тестовым HTTP-ответом, владение записями и обработка ошибок.
- Android workflow распаковывает исходный архив, применяет существующие исправления и `scripts/apply_redis_memory.py`, затем собирает APK.
- Workflow запускается вручную: Actions → Build Jarvis Android APK → Run workflow → ветка `fix-microphone-sensitivity`.

Для обновления поверх установленного APK необходим прежний ключ подписи (`JARVIS_DEBUG_KEYSTORE_B64`). Проверки без реального Redis не подтверждают работу облачного хранилища; после развёртывания нужен тест на устройстве.
