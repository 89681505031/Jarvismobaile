# Instagram ↔ Jarvis: ручное подтверждение сообщений (пилот)

Первый этап интеграции: сервер принимает **только подписанные Meta вебхуки** входящих сообщений,
временно показывает их владельцу и позволяет вручную подтвердить отправку ответа.
**Автоответы, публикации, OAuth, подключение ChatGPT и постоянное хранение пока НЕ реализованы.**
Это отдельный Node.js сервис, не часть Redis Memory Gateway. Доступна браузерная панель ручного подтверждения.

## Требования

- Профессиональный Instagram (Business или Creator) и Meta Developer App.
- Instagram API with Instagram Login; для сообщений нужно разрешение
  `instagram_business_manage_messages`. Пользователь должен сначала написать вашему аккаунту.
  Публикация и комментарии требуют отдельных разрешений и этапов разработки.
- Подключение Windsor.ai к ChatGPT настраивается **отдельно в самом ChatGPT** и не выдаёт
  приложению Jarvis токены Instagram.
- Node.js 22+, отдельный HTTPS-домен и конфигурация секретов **на сервере**.

Справочник Meta: https://www.postman.com/meta/workspace/instagram/documentation/23987686-9386f468-7714-490f-9bfc-9442db5c8f00

## Конфигурация

Задайте через защищённые переменные окружения на своём хостинге (не в APK, не в GitHub):

- `INSTAGRAM_APP_SECRET` — App Secret из Meta Developer App.
- `INSTAGRAM_WEBHOOK_VERIFY_TOKEN` — случайный секрет, не короче 32 символов; такой же укажите в Meta webhook.
- `INSTAGRAM_ACCOUNT_ID` — ID своего профессионального Instagram-аккаунта.
- `INSTAGRAM_ACCOUNT_TOKEN` — серверный access token с разрешением сообщений.
- `JARVIS_INSTAGRAM_ADMIN_TOKEN` — отдельный случайный ключ администратора, не короче 32 символов.
- `INSTAGRAM_GRAPH_VERSION` — необязательная версия API; по умолчанию `v26.0`.
- `PORT` — по умолчанию 8080.

Запуск: `npm test`, затем `npm start`. Настройте HTTPS reverse proxy.
В Meta настройте webhook callback `https://ваш-домен/webhook` и выбранный verify token.

## Панель владельца

После запуска откройте **https://ваш-домен/admin** на телефоне или ПК и введите
**отдельный** `JARVIS_INSTAGRAM_ADMIN_TOKEN`. Он не сохраняется в браузерном
`localStorage` или Android APK. Панель показывает входящие DM и позволяет
написать ответ. Перед отправкой появляется окно подтверждения.

В Android Jarvis Mobile: **Настройки → Instagram**. Разрешите приложению
Instagram в списке приложений, чтобы работала голосовая команда
«открой инстаграм»; сохраните HTTPS-адрес *своего* сервера и нажмите
«Открыть панель Direct». APK хранит только адрес, но не Meta-токены.

## Проверка

`GET /health` — только статус, никаких ключей. Сервис не означает, что Instagram уже подключён.
`GET /admin/inbox` — последние входящие сообщения с `Authorization: Bearer <JARVIS_INSTAGRAM_ADMIN_TOKEN>`.
`POST /admin/reply` — JSON `{"messageId":"...","text":"..." }` с тем же заголовком;
отправит ответ **только на верифицированное входящее сообщение** и только после ручного запроса.
При сетевой неопределённости повтор запрещён: проверьте сообщения в самом Instagram.

## Важно для эксплуатации

Память очереди **только в RAM**; при перезапуске входящие сообщения исчезнут.
Этот пилот рассчитан на **один процесс и тестовый аккаунт**. Нельзя ставить его в
production с несколькими репликами: перед этим нужны шифрованное постоянное хранение,
согласованный deduplication/atomic sending, безопасная админ-панель с входом,
защита от повторных webhook и обработка лимитов/окон сообщений Meta.
Не присылайте токены и пароли в чаты и не коммитьте их в репозиторий.
